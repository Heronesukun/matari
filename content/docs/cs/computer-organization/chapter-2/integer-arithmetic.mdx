# 整数运算：加减、溢出与标志位

固定 `n` 位硬件的整数加法本质上按模 `2^n` 计算：超出最高位的部分不会保存在结果寄存器中。

同一加法器可以服务无符号数和补码整数，但**判断结果是否有效的规则不同**。

## 补码加法：位相加，最高进位丢弃

### 标例 1｜`7 + (-3)`，8 位补码

```text
  00000111   (+7)
+ 11111101   (-3)
-----------
1 00000100
```

只保留低 8 位：

```text
00000100 = 4
```

最高进位丢弃后，结果正确。

## 减法：把减数取补再相加

```text
x - y = x + (-y)
```

硬件可以通过对 `y` 逐位取反，并把最低位进位输入设为 1，完成 `~y + 1`。

### 标例 2｜`37 - 52`

```text
37  = 00100101
52  = 00110100
-52 = 11001100
```

相加：

```text
00100101 + 11001100 = 11110001
```

`11110001` 取反加 1 得 `00001111`，所以结果是 `-15`。

## 无符号进位与带符号溢出不是一回事

### 无符号数看进位

8 位无符号 `255 + 1`：

```text
11111111 + 00000001 = 1 00000000
```

低 8 位结果为 0，最高进位为 1，说明无符号结果超出 `0..255`。

### 补码看符号是否异常

补码加法中，只有**两个同号数相加得到异号结果**才发生溢出：

```text
正 + 正 → 负：溢出
负 + 负 → 正：溢出
异号相加：不会发生补码溢出
```

### 标例 3｜`100 + 60`，8 位补码

```text
  01100100   100
+ 00111100    60
-----------
  10100000
```

两个正数得到最高位为 1 的负数解释，发生有符号溢出。数学结果 160 超过 8 位补码最大值 127。

注意：这次最高位可能没有产生无符号进位，但仍有有符号溢出。

## 减法的溢出判断

`x - y` 可以看作 `x + (-y)`。常用语言判断为：

```text
x 与 y 符号不同，且结果符号与 x 不同 → 溢出
```

例如 8 位补码 `100 - (-60) = 160`，超出范围。

## 常见状态标志

不同体系结构命名可能略有差异，常见含义如下：

- `CF`：最高位的进位或借位信息，常用于无符号运算；
- `OF`：补码有符号溢出；
- `ZF`：结果是否为 0；
- `SF` 或 `N`：结果最高位，反映补码结果符号；
- `PF`：某些体系结构中的奇偶校验标志。

不要把 `CF` 与 `OF` 混用。CPU 不知道程序想把位模式当有符号还是无符号，所以通常同时生成多个标志，由后续条件指令选择使用。

## 移位运算

### 逻辑左移

低位补 0，高位移出。对无溢出的无符号数，左移 1 位相当于乘 2。

### 逻辑右移

高位补 0，适合无符号数除以 2。

### 算术右移

高位补原符号位，用于补码有符号数近似除以 2，并保持符号。

```text
8 位 -8：11111000
算术右移 1 位：11111100 = -4
逻辑右移 1 位：01111100 = 124
```

两种右移对负数结果完全不同。

## 乘法与除法的硬件直觉

二进制乘法可以分解为：

```text
根据乘数当前位决定是否加被乘数
每轮移位
累加部分积
```

两个 `n` 位数的完整乘积可能需要 `2n` 位保存。只保留低 `n` 位时可能溢出。

二进制除法则反复进行比较、减法和移位，生成商位与余数。具体阵列乘法、Booth 算法和恢复/不恢复余数除法属于后续硬件细节，首次学习先掌握位宽和结果范围。

## 高频易错点

- 最高进位为 1 就认定补码溢出；
- 两个异号数相加仍判断有符号溢出；
- 做减法时忘记把减数取补；
- 负数右移一律高位补 0；
- 左移只写“乘 2”却不检查移出位和溢出；
- 忽略乘积可能需要双倍位宽；
- 根据结果最高位直接断言数学结果为负，而不先检查 `OF`。

## 30 秒速查

```text
固定 n 位加法：按模 2^n，低 n 位留下
减法：x-y = x + (~y+1)
无符号越界：看 CF
补码溢出：同号相加得异号，看 OF
逻辑右移：高位补 0
算术右移：高位补符号位
乘积完整保存通常需要 2n 位
```
