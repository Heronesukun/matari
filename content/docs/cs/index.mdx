# 计算机基础

计算机课程最容易出现两种低效学习方式：一种只背名词，知道“栈是后进先出”或“进程有多个状态”却不会执行操作；另一种一开始就陷入大量语法、硬件和内核细节，看完以后仍不知道题目或系统现象在考什么。

MATARI 采用分层路线：

```text
导入前置
→ 第一轮建立主干
→ A 组练习确认可用
→ 第二轮补扩展
→ B / C 组完成迁移
```

## 第一步不是立刻进入正文

根据课程选择导入或路线：

- [数据结构导入](/docs/cs/data-structure/chapter-0)：解决代码函数、数组、指针、动态内存、递归和取模的阅诹障碍；
- [计算机组成原理导入](/docs/cs/computer-organization/chapter-0)：解决位编号、位权、固定宽度、逻辑运算和移位的阅读障碍；
- [操作系统学习路线](/docs/cs/operating-system)：先确认程序阅读、状态跟踪、地址和中断的最低前置，再按系统边界、并发、内存与持久化逐章学习。

导入章节只补“进入正文所需的最低基础”，不会把一门编程语言、数字逻辑课程或内核源码完整塞进前置部分。

## 阅读正文时关注六件事

1. **对象是什么**：数据、节点、位模式、寄存器、进程、页还是文件？
2. **状态怎么表示**：哪些变量、表、队列、寄存器或映射共同描述当前状态？
3. **事件如何改变状态**：一次插入、移位、系统调用、调度或缺页到底改变了什么？
4. **约束在哪里**：容量、边界、位宽、互斥、权限、实时期限还是持久化条件？
5. **代价是什么**：时间、空间、硬件复杂度、切换开销、精度或可靠性？
6. **失败怎样表现**：越界、溢出、竞态、死锁、抖动、不一致还是越权？

## 当前学习入口

- [数据结构](/docs/cs/data-structure)：导入后依次学习复杂度、线性表、栈与队列，再进入树、图、查找和排序。
- [计算机组成原理](/docs/cs/computer-organization)：导入后先学习数据表示与运算，再连接存储、指令和 CPU。
- [操作系统](/docs/cs/operating-system)：课程路线、章节学习合同和创作验收规范已经建立；正文会从导入与系统调用边界开始逐章建设。

## 推荐自学动作

每看完一个标例，先不要继续向下滚动。尝试自己回答：

- 我为什么选择这个结构、机制或策略？
- 当前状态由哪些量表示？
- 下一事件会更新哪些状态？
- 边界和失败条件是什么？
- 若输入规模、位宽、资源数量或事件顺序改变，结论会不会变？

如果只能复述定义，却无法手动执行一次操作流程，就回到本章“开始前”页面或导入章节补对应前置。
