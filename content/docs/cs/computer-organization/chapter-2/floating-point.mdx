# 浮点表示与运算：范围与精度的交换

定点整数把有限位都用于固定位置的数值。浮点数把一部分位用于指数，使小数点位置可以移动，从而获得更大表示范围，但精度不再均匀。

浮点数可抽象为：

```text
符号 × 有效数 × 基数^指数
```

## IEEE 754 单精度结构

32 位单精度：

```text
1 位符号 S | 8 位阶码 E | 23 位尾数字段 F
```

正常规格化数的值为：

```text
(-1)^S × (1.F) × 2^(E-127)
```

这里：

- `S=0` 为正，`S=1` 为负；
- 阶码使用偏置 127 保存；
- 规格化数有效数最高位固定为 1，因此这个 1 不实际存储，称为隐藏位。

64 位双精度则是：1 位符号、11 位阶码、52 位尾数，偏置为 1023。

## 标例 1｜把 5.75 编成单精度

先转二进制：

```text
5.75 = 101.11₂
```

规格化：

```text
101.11₂ = 1.0111₂ × 2^2
```

因此：

```text
S = 0
实际指数 = 2
E = 2 + 127 = 129 = 10000001₂
F = 01110000000000000000000
```

最终字段：

```text
0 | 10000001 | 01110000000000000000000
```

**识别流程：**转二进制 → 规格化 → 加偏置 → 去掉隐藏的最高位 1。

## 标例 2｜从字段读值

给定：

```text
1 | 10000000 | 01000000000000000000000
```

- 符号为负；
- 实际指数 `128-127=1`；
- 有效数为 `1.01₂=1.25`。

所以数值为：

```text
-1.25 × 2^1 = -2.5
```

## 阶码特殊值

### `E=0`

- `F=0`：表示 `+0` 或 `-0`；
- `F≠0`：表示非规格化数（次正规数），用于逐渐接近 0。

非规格化数没有隐藏的最高位 1，形式近似为 `0.F × 2^(1-bias)`。

### `E` 全为 1

- `F=0`：正无穷或负无穷；
- `F≠0`：NaN，表示“不是一个普通数值”，如某些非法运算结果。

因此不能把所有阶码字段都直接按 `E-bias` 解释。

## 浮点加减为什么比整数复杂

计算 `a+b` 通常经过：

1. **对阶**：让两个数指数相同，较小指数的有效数右移；
2. **有效数加减**；
3. **规格化**：调整有效数和指数；
4. **舍入**：位数超出尾数字段时按舍入规则处理；
5. **判断上溢、下溢和特殊值**。

### 标例 3｜理解对阶

```text
1.5 = 1.1₂ × 2^0
0.25 = 1.0₂ × 2^-2
```

把第二个数对到指数 0：

```text
0.25 = 0.01₂ × 2^0
```

相加：

```text
1.10₂ + 0.01₂ = 1.11₂ = 1.75
```

较小数对阶时会右移。如果指数差很大，它的有效位可能全部被舍掉，这就是“大数加很小的数结果不变”的原因。

## 为什么 0.1 经常不能精确表示

十进制 `0.1` 的二进制展开是无限循环。固定 23 或 52 位尾数只能保存近似值，因此浮点运算通常存在舍入误差。

所以程序中不应简单用 `a+b==c` 判断两个经过多次计算的浮点结果是否完全相等，常用允许误差范围比较。

## 浮点数的范围与精度

- 指数位主要决定可表示范围；
- 尾数位主要决定有效精度；
- 数值越大，相邻可表示数之间的间隔通常越大；
- 浮点数不是实数的连续覆盖，而是一组离散点。

## 高频易错点

- 把尾数字段 `F` 直接当成完整有效数，忘记隐藏位；
- 阶码忘记减偏置；
- `E=0` 或全 1 时仍按普通规格化数解释；
- 认为浮点数可以精确表示所有十进制小数；
- 浮点加法不对阶就直接相加尾数；
- 认为浮点数只要位宽更大就不会溢出或舍入；
- 把 `+0` 与 `-0` 的位模式相同化。

## 30 秒速查

```text
单精度：1 / 8 / 23，bias=127
双精度：1 / 11 / 52，bias=1023
规格化值：(-1)^S × 1.F × 2^(E-bias)
编码：二进制 → 规格化 → 加偏置 → 去隐藏 1
加减：对阶 → 尾数运算 → 规格化 → 舍入
E=0 与 E=全1 是特殊情况
```
