# 数组、结构体、指针与内存：看懂数据放在哪里

数据结构代码经常同时描述两层内容：**数据本身是什么，以及数据被放在哪里。** 数组使用连续位置，链表使用地址连接节点。

## 数组：下标是位置，不是元素个数

```c
int a[5] = {10, 20, 30, 40, 50};
```

长度为 5，但合法下标是：

```text
0, 1, 2, 3, 4
```

因此 `a[2]` 是 30，`a[5]` 越界。

正文通常把当前有效元素个数单独保存为 `length`。数组容量和当前长度不是一回事：容量可能是 100，当前只使用了前 6 个位置。

## 结构体：把共同描述一个对象的字段放在一起

```c
#define MAX_SIZE 100

typedef struct {
    int data[MAX_SIZE];
    int length;
} SqList;
```

一个 `SqList` 同时包含：

- `data`：保存元素的数组；
- `length`：当前有效元素个数。

若变量本身是对象，使用点号：

```c
SqList L;
L.length = 0;
```

若变量保存对象地址，使用箭头：

```c
SqList *p = &L;
p->length = 0;
```

此时 `p->length` 与 `(*p).length` 含义相同，箭头只是更易读的写法。

## 指针：保存的是地址

链表节点可以写成：

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

```c
Node *p;
```

表示 `p` 可以保存某个 `Node` 的地址。若 `p` 指向一个节点：

- `p->data`：该节点的数据；
- `p->next`：下一个节点的地址；
- `p == NULL`：当前没有指向有效节点。

`NULL` 不是一个普通节点，它表示“这里没有地址”。访问 `NULL->data` 是错误的。

### `&` 与 `*` 的最小理解

```c
int x = 8;
int *p = &x;
*p = 10;
```

- `&x`：取得 `x` 的地址；
- `p`：保存这个地址；
- `*p`：访问该地址中的值；
- 最后一行执行后，`x` 变为 10。

在声明 `Node *p` 中，星号表示 `p` 是指针；在表达式 `*p` 中，星号表示访问指向的对象。第一次学习只需先区分这两种位置。

## 动态内存：节点通常在运行时创建

```c
Node *node = malloc(sizeof(Node));
if (node == NULL) return false;

node->data = value;
node->next = NULL;
```

- `sizeof(Node)`：一个节点需要多少字节；
- `malloc(...)`：申请这块内存并返回首地址；
- 申请失败时可能得到 `NULL`；
- 不再需要节点时应使用 `free(node)` 释放。

真实 C 程序需要包含 `<stdlib.h>`。MATARI 有时会省略头文件，因为重点是节点关系。

## 为什么链表插入的顺序不能反

已知 `p` 指向某节点，要把 `node` 插入到它后面：

```c
node->next = p->next;
p->next = node;
```

先让新节点记住原来的后继，再让 `p` 指向新节点。

若先执行：

```c
p->next = node;
```

原后继的地址就可能丢失，因为此时还没有任何地方保存它。

## 删除节点时也要先保存地址

```c
Node *q = p->next;
p->next = q->next;
free(q);
```

过程是：

1. `q` 保存待删除节点地址；
2. 前驱绕过它，连接到后继；
3. 最后释放 `q`。

释放后不要再访问 `q->data` 或 `q->next`。

## 常见误区

- 把数组长度 5 误认为最后下标是 5；
- 混用对象的 `.` 与指针的 `->`；
- 没检查 `NULL` 就访问节点；
- 修改指针前没有保存原来的链；
- `free` 后继续访问已经释放的节点；
- 只会画节点，不知道每个指针变量当前指向谁。
