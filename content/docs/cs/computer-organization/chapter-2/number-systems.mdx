# 进位制与编码：先读懂位权

进位制的本质是**位置决定权值**。在 `r` 进制中，每一位的权值是 `r` 的整数次幂。

例如二进制数 `101101.01` 表示：

```text
1×2^5 + 0×2^4 + 1×2^3 + 1×2^2 + 0×2^1 + 1×2^0
+ 0×2^-1 + 1×2^-2
```

所以其十进制值为 `45.25`。

## 二进制转十进制：按位权展开

### 标例 1

把 `110101₂` 转为十进制：

```text
1×32 + 1×16 + 0×8 + 1×4 + 0×2 + 1×1 = 53
```

**识别：**从最低位开始，权值依次是 `1,2,4,8,...`。

## 十进制整数转二进制：除 2 取余，逆序排列

### 标例 2｜45 转二进制

```text
45 ÷ 2 = 22 ... 1
22 ÷ 2 = 11 ... 0
11 ÷ 2 =  5 ... 1
 5 ÷ 2 =  2 ... 1
 2 ÷ 2 =  1 ... 0
 1 ÷ 2 =  0 ... 1
```

把余数从下向上读：

```text
45₁₀ = 101101₂
```

**为什么要逆序：**第一次得到的是最低位，最后一次才得到最高位。

## 十进制小数转二进制：乘 2 取整，顺序排列

### 标例 3｜0.625 转二进制

```text
0.625 × 2 = 1.25  → 整数部分 1
0.25  × 2 = 0.5   → 整数部分 0
0.5   × 2 = 1.0   → 整数部分 1
```

按出现顺序读取：

```text
0.625₁₀ = 0.101₂
```

有些十进制小数无法用有限二进制位精确表示，例如 `0.1`。这不是计算机“算错”，而是进位制表示能力的限制。

## 二进制与十六进制：每 4 位一组

因为 `16=2^4`，每个十六进制数字正好对应 4 个二进制位。

```text
二进制  0000 0001 0010 ... 1001 1010 1011 ... 1111
十六进制   0    1    2  ...   9    A    B  ...   F
```

### 标例 4

```text
1011 0110 1111₂ = B6F₁₆
```

从小数点向左右分别每 4 位分组，不足时补 0：

```text
110101.101₂
= 0011 0101 . 1010₂
= 35.A₁₆
```

补 0 只能加在最高位左侧或小数最低位右侧，不能改变位权位置。

## 八进制：每 3 位一组

因为 `8=2^3`，二进制与八进制每 3 位对应一个数字。方法与十六进制相同。

## 位模式与数值不是一回事

`11111101` 可以被解释为：

- 无符号整数：253；
- 8 位补码整数：-3；
- 某个字符编码的一部分；
- 浮点数字段中的 8 个比特。

硬件看到的只是位模式。必须由指令和数据类型说明如何解释。

## BCD：用 4 位保存一个十进制数字

8421 BCD 将每个十进制数字单独编码：

```text
59₁₀ → 0101 1001(BCD)
```

它不是普通二进制 `59`。普通二进制为 `0011 1011₂`。

BCD 便于十进制显示和金融十进制处理，但存储效率低于纯二进制。

## 字符编码补充

字符也需要编码。ASCII 使用数值表示英文字母、数字和控制字符，例如字符 `'0'` 与数值 0 的位模式不同。

学习计算题时先问：题目给的是字符、字符编码，还是数值本身。

## 高频易错点

- 十进制整数除 2 后按正序读取余数；
- 小数乘 2 的结果反向读取；
- 二转十六进制分组方向错误；
- 为了补足 4 位在错误位置补 0；
- 把 BCD 当成普通二进制；
- 没有说明位模式按哪种类型解释。
