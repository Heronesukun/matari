# 队列：按到达顺序处理元素

队列在队尾插入、队头删除：

```text
enqueue：入队
front/peek：查看队头
dequeue：队头出队
```

## 普通顺序队列为什么会“假溢出”

若数组只让 `rear` 一直向右移动，即使前面元素已经出队，数组前部空位也无法复用。当 `rear` 到达末尾时，看似已满，但实际还有空槽，这叫假溢出。

解决办法是把数组首尾逻辑相连，形成循环队列。

## 循环队列：本文采用空出一个槽位的约定

数组容量为 `MAX_SIZE`：

- `front` 指向当前队头元素；
- `rear` 指向下一个可写位置；
- 空队：`front == rear`；
- 满队：`(rear + 1) % MAX_SIZE == front`；
- 队列长度：`(rear - front + MAX_SIZE) % MAX_SIZE`；
- 最多保存 `MAX_SIZE - 1` 个元素。

### 入队

```c
bool enqueue(Queue *Q, int x) {
    if ((Q->rear + 1) % MAX_SIZE == Q->front) return false;
    Q->data[Q->rear] = x;
    Q->rear = (Q->rear + 1) % MAX_SIZE;
    return true;
}
```

### 出队

```c
bool dequeue(Queue *Q, int *x) {
    if (Q->front == Q->rear) return false;
    *x = Q->data[Q->front];
    Q->front = (Q->front + 1) % MAX_SIZE;
    return true;
}
```

## 标例 1｜计算长度

容量 `MAX_SIZE=8`，当前 `front=6`、`rear=2`。

```text
length = (2 - 6 + 8) % 8 = 4
```

说明队列元素跨过了数组末尾，逻辑顺序可能位于下标 `6,7,0,1`。

**复盘：**循环队列的大小关系不能直接用 `rear-front` 判断，必须取模修正。

## 为什么要浪费一个槽位

如果所有槽位都允许使用，那么 `front==rear` 既可能表示空，也可能表示满，状态无法区分。

常见解决方案有三种：

1. 空出一个槽位；
2. 额外维护元素个数 `size`；
3. 额外维护最近一次操作标志。

题目必须先明确采用哪一种约定，公式不能混用。

## 链式队列

常见做法同时维护队头指针 `front` 和队尾指针 `rear`：

- 入队在尾部连接新节点；
- 出队删除头部节点；
- 两个操作都可为 `Θ(1)`。

若带头结点，空队时通常有 `front==rear` 且二者都指向头结点。删除最后一个有效节点后，要让 `rear` 重新指回头结点，否则会留下失效尾指针。

## 双端队列补充

双端队列允许两端插入和删除。若进一步限制某一端只能插入或只能删除，会形成输入受限或输出受限双端队列。

它们适合用来理解操作序列可能性，但初学阶段先确保普通栈和循环队列操作无误。

## 高频易错点

- 混用“`rear` 指向队尾元素”和“`rear` 指向下一空位”的公式；
- 忘记取模，越过数组边界；
- 空出一格时仍认为最大元素数等于数组容量；
- 出队后忘记移动 `front`；
- 链队删除最后节点后没有更新 `rear`；
- 用 `rear > front` 判断循环队列是否非空。
