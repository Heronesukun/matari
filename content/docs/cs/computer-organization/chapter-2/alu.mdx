# 运算器与 ALU：位运算如何变成硬件动作

前面手算的是编码规则。硬件需要用组合逻辑把这些规则实现为稳定的电信号变换。

ALU（算术逻辑单元）通常能够完成：

- 加法与减法；
- 按位与、或、异或、取反；
- 比较；
- 配合移位器完成逻辑和算术移位；
- 生成零、符号、进位、溢出等状态标志。

## 一位全加器

一位加法需要三个输入：

```text
A：当前位操作数
B：当前位操作数
Cin：低一位传来的进位
```

输出：

```text
Sum：当前位和
Cout：向高一位产生的进位
```

逻辑关系可写为：

```text
Sum  = A XOR B XOR Cin
Cout = (A AND B) OR (Cin AND (A XOR B))
```

把多个全加器串起来，就得到多位加法器。

## 串行进位为什么会慢

最简单的多位加法器让低位 `Cout` 作为高位 `Cin`。最高位结果必须等待进位逐级传播，位数越多，关键路径越长。

超前进位加法器通过提前计算“本位是否生成进位”和“是否传播进位”，并行得到更高位进位，降低延迟，但电路更复杂。

这里要记住的取舍是：

```text
更快的进位计算 ↔ 更多组合逻辑和硬件复杂度
```

## 一个加法器如何完成减法

减法使用补码：

```text
A - B = A + (~B) + 1
```

硬件可用控制信号决定是否让 `B` 经过异或门取反，并把最低位 `Cin` 置 1。这样同一套加法电路同时支持加减。

## 逻辑运算为什么按位独立

按位与、或、异或的每一位只依赖当前位输入，不产生跨位进位，因此天然并行。

例如：

```text
10110100
AND 01101110
=   00100100
```

这些操作常用于掩码、设置位、清除位和比较差异。

## 移位器

移位器负责把位整体移动：

- 逻辑左移：低位补 0；
- 逻辑右移：高位补 0；
- 算术右移：高位补符号位；
- 循环移位：移出的位回到另一端。

桶形移位器可以在一次组合逻辑过程中移动多个位置，常用于高性能数据通路。

## ALU 控制与结果选择

可以把 ALU 想成多个候选结果并行产生，再由控制信号选择其中一个：

```text
控制码 000 → AND
控制码 001 → OR
控制码 010 → ADD
控制码 110 → SUB
控制码 ... → 其他操作
```

具体编码由处理器设计决定，不必把某个示例编码当成通用标准。

## 标志位如何生成

以加法结果为例：

- `ZF`：所有结果位都为 0；
- `SF`：结果最高位；
- `CF`：最高位加法产生的进位；
- `OF`：最高位的“进入进位”和“输出进位”不一致，等价于补码同号相加得异号。

后续条件跳转指令会根据有符号或无符号语义选择不同标志组合。

## 标例｜同一位结果，两种比较语义

8 位计算：

```text
11111111 + 00000001 = 00000000
```

- 按无符号：`255+1` 越界，`CF=1`；
- 按补码：`-1+1=0`，没有有符号溢出，`OF=0`；
- 结果为 0，`ZF=1`。

同一次硬件加法可以同时产生这些标志，程序再决定使用哪一种语义。

## 乘除部件的基本组成

乘法器通常结合：

- 加法器；
- 移位寄存器；
- 部分积寄存器；
- 控制逻辑。

除法器则结合比较、减法、移位和商位生成。高性能实现可能采用并行阵列或流水化，但核心仍围绕部分结果和位移。

## 高频易错点

- 认为 ALU 能“理解”有符号和无符号，而忽略位模式相同；
- 把控制码示例当成所有 CPU 的固定编码；
- 只记 `CF`、`OF` 名称，不理解它们服务的语义；
- 认为逻辑运算也需要逐位传递进位；
- 只会画加法结果，不会解释减法如何复用加法器；
- 忽略更快电路通常需要更多硬件资源。

## 30 秒速查

```text
全加器：A、B、Cin → Sum、Cout
多位加法：低位进位向高位传播
减法：B 取反，Cin=1，复用加法器
逻辑运算：各位独立
移位器：负责位位置变化
ALU：控制信号选择算术、逻辑或比较结果
标志：ZF / SF / CF / OF
```
