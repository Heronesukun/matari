# 操作系统学习路线

操作系统不是一组需要背诵的名词，也不只是“管理硬件的软件”。它真正解决的是：**怎样让多个程序安全、并发、可控地共享处理器、内存、设备和持久化数据。**

学完这门课，你不应只会复述“进程有三种状态”或“页面置换有 FIFO”。你应该能够跟踪一次状态变化、选择合适的机制、检查使用条件，并解释系统为什么会阻塞、竞争、缺页、死锁或丢失数据。

## 先建立五个持续追问的问题

学习任何操作系统主题时，都先问：

1. **当前对象是谁**：进程、线程、页、页框、文件、设备请求还是权限主体？
2. **状态怎样表示**：哪些表、队列、寄存器、计数器或位共同描述当前状态？
3. **事件怎样改变状态**：系统调用、中断、调度、加锁、缺页或 I/O 完成后，哪些量发生变化？
4. **共享资源受什么约束**：容量、互斥、顺序、权限、实时期限还是持久化要求？
5. **失败表现是什么**：饥饿、活锁、死锁、抖动、越权、崩溃不一致还是性能退化？

如果一页内容只能告诉你“它是什么”，却不能帮助你回答这五个问题，它还没有达到 MATARI 的完成标准。

## 第一次进入前需要什么

首轮学习只要求以下最低前置：

- 能读懂变量、循环、函数调用和简单 C 风格伪代码；
- 知道栈、队列、链表和位图分别适合表示什么；
- 认识 CPU、寄存器、主存、地址、指令、中断和 I/O 的基本含义；
- 能根据一张表或一段时间线逐步更新状态。

不要求先会写内核，也不要求先掌握某个真实操作系统的源码。课程会在导入章补齐“用户程序—硬件—内核”之间最小但必要的连接。

前置不稳时，可先复习：

- [数据结构导入](/docs/cs/data-structure/chapter-0)
- [复杂度](/docs/cs/data-structure/chapter-1)
- [计算机组成原理导入](/docs/cs/computer-organization/chapter-0)
- [数据表示与运算](/docs/cs/computer-organization/chapter-2)

## 示例与平台约定

课程使用接近 C 的伪代码和 POSIX 风格系统调用作为主要载体，因为它们便于展示进程、文件和系统调用边界。凡是只适用于 Linux、POSIX、xv6 或其他具体系统的行为，正文必须明确标注，不能把一种实现写成所有操作系统的通用规则。

## 三条主线，一条贯穿约束

```text
虚拟化：一个 CPU 和一份内存，怎样呈现为多个独立运行环境
并发：多个执行流怎样交错，又怎样安全协作
持久化：数据怎样经过文件系统和设备，在掉电后仍保持可恢复
保护：谁能访问什么，以及系统如何限制故障和越权的影响范围
```

课程章节会分别展开，但学习时要不断把它们重新连接起来。例如，一次 `read` 可能同时涉及系统调用边界、进程阻塞、调度切换、页缓存、设备中断和文件系统元数据。

## 推荐章节顺序

| 阶段 | 章节 | 第一轮要获得的能力 | 第二轮再补 |
| --- | --- | --- | --- |
| 0 | 导入：状态与执行路径 | 区分程序、进程、线程、用户态、内核态；能读状态表和时间线 | 最小汇编、内核栈、启动过程 |
| 1 | 操作系统角色与系统调用 | 解释抽象、资源管理与隔离；跟踪一次系统调用往返 | 内核结构、机制与策略、启动与异常分类 |
| 2 | 进程、线程与上下文切换 | 更新进程状态；区分进程与线程；理解创建、等待和切换 | 进程间通信、写时复制、多线程实现 |
| 3 | 处理机调度 | 根据到达与运行时间画调度时间线并计算指标 | 多级反馈队列、多核调度、实时调度 |
| 4 | 并发与同步 | 识别竞态；用锁、信号量或条件变量保护共享状态 | 读写锁、监视器、无锁思想与并发缺陷诊断 |
| 5 | 死锁与活性 | 判断死锁条件；区分死锁、饥饿与活锁 | 银行家算法、检测恢复与工程取舍 |
| 6 | 地址空间与基本内存管理 | 区分虚拟地址和物理地址；完成分配与基础地址转换 | 分段、伙伴系统、碎片权衡 |
| 7 | 分页与虚拟内存 | 跟踪页表、TLB、缺页和置换；判断抖动风险 | 多级页表、写时复制、内存映射与工作集 |
| 8 | 设备与 I/O | 比较轮询、中断和 DMA；跟踪阻塞 I/O 的事件链 | 磁盘调度、SSD 特性、缓冲与假脱机 |
| 9 | 文件系统与持久化 | 从路径解析到数据块定位；理解分配、缓存和崩溃一致性 | 日志、恢复、空闲空间、链接和高级文件系统 |
| 10 | 保护、虚拟化与可靠性综合 | 解释访问控制与隔离；把全课程机制串成一次完整执行 | 虚拟机、容器、实时系统、容错与安全扩展 |

这些标签表示学习优先级，不代表未经统计的考试频率。正文建设时，每章还会拆成“开始前—核心页面—精选练习—可选实验”。

## 遇到问题时先走哪条路

| 看到的现象或题型 | 先定位到 | 第一检查项 |
| --- | --- | --- |
| 程序调用服务后进入内核 | 系统调用与异常 | 触发原因、特权级变化、返回位置 |
| 程序运行、等待、再次运行 | 进程状态与调度 | 触发事件、所在队列、是否抢占 |
| 多线程结果偶尔错误 | 并发与同步 | 哪些操作不是原子的，哪些状态被共享 |
| 所有执行流都不再前进 | 死锁与活性 | 等待关系、资源占有、是否存在环路 |
| 给出逻辑地址、页号和页表 | 地址转换 | 页大小、字段划分、有效位与权限位 |
| 内存不足并发生频繁缺页 | 虚拟内存 | 驻留集、访问局部性、置换范围 |
| 进程发起 I/O 后阻塞 | 设备与 I/O | 请求由谁保存，完成事件如何通知 |
| 给出路径、目录项和索引节点 | 文件系统 | 名称解析、元数据、数据块映射 |
| 掉电后文件长度或内容异常 | 持久化与恢复 | 写入顺序、缓存、原子更新边界 |
| 某主体能否访问某对象 | 保护与安全 | 身份、权限、保护域与默认策略 |

## 每章分两轮学习

### 第一轮：先形成可执行主干

每章先完成四件事：

1. 说出该机制解决的资源或抽象问题；
2. 用表格、队列、时间线或地址字段表示状态；
3. 手动执行一个标准过程；
4. 完成 A 组必会主干练习，并能说明第一步为什么这样做。

### 第二轮：再比较策略与边界

主干稳定后再学习：

- 多种算法的性能、公平性和实现代价；
- 失败模式、异常路径和恢复策略；
- 多核、实时、虚拟化、安全与容错扩展；
- B 组高频应用和 C 组补充辨识。

## 操作系统题目不能省略的条件

调度、同步、地址转换和存储题常因条件不完整而出现多解。MATARI 的题目必须明确：

- 调度的到达时刻、运行时间、时间片、优先级方向、抢占规则和同分处理；
- 并发操作的初值、原子操作、允许的交错和唤醒语义；
- 死锁题的资源种类、实例数量、已分配量和最大需求；
- 地址题的地址宽度、页大小、页表项大小、有效位和 TLB 假设；
- 置换题的页框数、引用串、初始状态和全局或局部置换范围；
- I/O 与磁盘题的初始位置、移动方向、请求队列和计时代价；
- 文件系统题的块大小、指针大小、索引结构、缓存与持久化假设。

条件不完整时，应先指出缺失信息，而不是默默补一个答案。

## 课程完成后的综合检验

学习完成后，你应该能独立解释一条完整路径：

```text
用户程序发出文件读取请求
→ 进入内核并检查参数与权限
→ 进程因等待数据而阻塞
→ 调度器选择另一个可运行线程
→ 文件系统解析路径并定位数据块
→ 设备驱动提交请求，控制器完成传输
→ 中断唤醒原进程
→ 必要时完成地址映射与数据复制
→ 系统调用返回用户态
```

能够讲清这条路径中“对象、状态、事件、约束和失败点”，才说明各章已经连接成一个系统，而不是十组孤立名词。
