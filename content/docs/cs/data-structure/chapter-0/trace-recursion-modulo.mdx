# 状态跟踪、递归与取模：把代码一步一步执行出来

第一次学习数据结构时，最可靠的方法不是在脑中“想象代码大概会怎样”，而是把每一步后的状态写下来。

## 状态表只记录会改变结论的量

例如顺序表 `[10, 20, 30]` 在位置 1 插入 99，代码从后向前移动：

```c
for (int j = L->length; j > pos; j--) {
    L->data[j] = L->data[j - 1];
}
L->data[pos] = 99;
L->length++;
```

可以画成：

| 步骤 | `j` | 有效区域或关键变化 |
|---|---:|---|
| 初始 | — | `[10, 20, 30, _]`, `length = 3` |
| 移动 1 | 3 | `[10, 20, 30, 30]` |
| 移动 2 | 2 | `[10, 20, 20, 30]` |
| 写入 | — | `[10, 99, 20, 30]` |
| 更新长度 | — | `length = 4` |

不要记录所有无关变量。只记录循环位置、指针和结构内容等关键状态。

## 赋值要按顺序执行

```c
next = cur->next;
cur->next = prev;
prev = cur;
cur = next;
```

这四行不能同时发生。阅读链表反转时，每执行一行都要问：

- `next` 当前保存谁；
- 已反转部分的入口是谁；
- 未处理部分的入口是谁。

很多指针错误来自把多行赋值当成一个整体，忽略了前一行已经改变状态。

## 递归：函数暂时停下，等待更小问题返回

```c
int sum_to(int n) {
    if (n == 0) return 0;
    return n + sum_to(n - 1);
}
```

计算 `sum_to(3)` 时：

```text
sum_to(3)
等待 3 + sum_to(2)
  等待 2 + sum_to(1)
    等待 1 + sum_to(0)
      返回 0
    返回 1
  返回 3
返回 6
```

需要先认识两个部分：

- **终止条件**：`n == 0`，否则会无限调用；
- **规模缩小**：每次变成 `n - 1`。

复杂度章节会利用调用层数计算时间和调用栈空间。现阶段不要求你独立设计递归，只要求能画出调用链。

## 抽象操作也有前置条件

```c
pop(S)
```

并不表示“无论如何都能弹出”。执行前通常需要：

```text
栈是否为空？
若不为空，栈顶是谁？
弹出后 top 如何改变？
```

同理，`dequeue(Q)` 前要检查队列是否为空。正文会明确失败时返回 `false`、特殊值，还是通过输出参数返回结果。

## 取模 `%`：让下标回到开头

```text
7 % 5 = 2
10 % 5 = 0
```

循环队列常写：

```c
rear = (rear + 1) % M;
```

若 `M = 8`：

| 原 `rear` | 加 1 | `% 8` 后 |
|---:|---:|---:|
| 2 | 3 | 3 |
| 6 | 7 | 7 |
| 7 | 8 | 0 |

因此下标走到数组末尾后，会回到 0。取模只负责“绕回”，并不自动判断队列是空还是满；空满还取决于 `front`、`rear` 的定义和额外约定。

## 手动执行时的固定模板

```text
1. 写出初始状态
2. 标出当前要执行的语句
3. 只修改这条语句涉及的量
4. 检查循环或递归是否继续
5. 写出最终返回值和最终结构
```

若你能稳定按这个模板执行代码，就已经具备进入正文所需的阅读能力。
