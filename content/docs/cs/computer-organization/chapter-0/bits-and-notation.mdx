# 位、字节与书写约定：先看清每一位的位置

## 位与字节

- **bit（位）**：只能取 0 或 1；
- **byte（字节）**：通常由 8 位组成；
- **word（字）**：处理器一次自然处理的数据宽度，具体可能是 16、32、64 位等，不能脱离体系结构固定理解。

正文写“8 位数”时，表示必须保留或解释 8 个二进制位置。前导 0 也属于位模式的一部分：

```text
00000101
```

是一个完整的 8 位模式，而不只是写成 `101` 的十进制数 5。

## 位编号从右向左开始

以 8 位模式为例：

```text
位编号    7 6 5 4 3 2 1 0
位模式    1 0 1 1 0 0 1 0
```

- 最右侧是第 0 位，叫 **LSB**（最低有效位）；
- 最左侧是第 7 位，叫 **MSB**（最高有效位）。

“第 3 位”通常指权重为 `2^3` 的那个位置，不是从左边数第三个字符。

## 常见书写方式

| 写法 | 含义 |
|---|---|
| `1010₂` | 下标 2 表示二进制 |
| `0b1010` | 程序中常见的二进制前缀写法 |
| `A₁₆` | 下标 16 表示十六进制 |
| `0xA` | 程序中常见的十六进制前缀写法 |
| `10₁₀` | 十进制 10 |

这三种写法可以表示同一个数值：

```text
1010₂ = 0b1010 = A₁₆ = 0xA = 10₁₀
```

但在固定位宽题中，还要补足所需位数，例如 8 位写成 `00001010`。

## 十六进制为什么常用于看二进制

一个十六进制数字恰好对应 4 个二进制位：

```text
0000 → 0
0001 → 1
...
1010 → A
...
1111 → F
```

因此：

```text
1101 0110₂ = D6₁₆
```

分组时从二进制小数点向左右分别按 4 位分组。整数部分不足 4 位时在左侧补 0，小数部分不足时在右侧补 0。

## 字段分隔不是额外的位

浮点数可能写成：

```text
0 | 10000001 | 01110000000000000000000
```

竖线只用于阅读，表示“符号字段、阶码字段、尾数字段”。它不占位，也不会被存入机器。

同理，空格常用于每 4 位或每 8 位分组：

```text
11111111 10110110
```

实际仍是一串连续的 16 位。

## 先别急着给位模式赋值

看到：

```text
10000000
```

先问：

1. 是几位？这里是 8 位；
2. 按什么规则解释？无符号、补码还是字段？

只有规则确定后才能决定它表示 128、-128，还是别的含义。
