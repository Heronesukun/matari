# 顺序表还是链表：把复杂度表变成选择

只背下面这张表还不够，关键是理解题目给了什么条件。

| 操作 | 顺序表 | 单链表 |
|---|---:|---:|
| 按下标访问 | `Θ(1)` | `Θ(n)` |
| 按值查找 | `Θ(n)` | `Θ(n)` |
| 已知位置后插入 | 可能移动，最坏 `Θ(n)` | 若已知前驱，`Θ(1)` |
| 已知位置删除 | 可能移动，最坏 `Θ(n)` | 若已知前驱，`Θ(1)` |
| 存储空间 | 连续，几乎无指针开销 | 分散，每节点有指针开销 |
| 扩容 | 固定数组受容量限制；动态数组需搬迁 | 可逐节点申请 |
| 缓存局部性 | 通常较好 | 通常较差 |

## 决策 1｜是否需要频繁随机访问

若算法经常访问第 `i` 个元素、做二分查找或使用下标计算邻居，顺序表更合适。

链表虽然可以表示相同逻辑顺序，但每次访问第 `i` 个位置都要从头走，代价会被放大。

## 决策 2｜插入删除位置是否已经拿到节点

题目说“在节点 `p` 后插入”时，链表修改是常数时间。

题目说“在第 `i` 个位置插入”时，链表通常先花 `Θ(n)` 找前驱。此时不能只写插入 `Θ(1)`。

## 决策 3｜规模是否稳定

- 元素上限明确、结构简单：静态顺序表容易实现；
- 元素数量频繁变化且无法预估：链表不需要整体扩容；
- 工程中动态数组也能自动扩容，不能简单认为“长度变化就一定用链表”。

## 决策 4｜内存与实际性能

链表减少了中间插删时的元素搬移，但每个节点额外保存指针，并且节点分散会降低缓存局部性。

因此在很多实际程序里，即使理论上需要偶尔中间插删，动态数组仍可能更快。考试题通常先按给定抽象模型分析；工程选择还要考虑常数开销和内存布局。

## 标例｜维护一组任务

场景 A：任务经常按编号读取，偶尔追加。

- 优先顺序表或动态数组；
- 按编号访问 `Θ(1)`；
- 尾部追加均摊 `Θ(1)`。

场景 B：系统已经持有某任务节点，经常在它后面插入新任务或删除下一任务。

- 链表更自然；
- 已知节点附近修改 `Θ(1)`；
- 不需要整体移动后续元素。

## 高频题型映射

| 题目语言 | 优先想到 |
|---|---|
| 原地删除满足条件的多个数组元素 | 读写双指针 |
| 两个有序线性表合并 | 双指针或双链游走 |
| 链表倒数第 `k` 个 | 快慢指针 |
| 判断链表是否有环 | 快慢指针速度差 |
| 单链表反转 | 三指针断链重接 |
| 在已知节点前插入 | 找前驱，或利用数据交换技巧（需看限制） |

## 一句话结论

```text
顺序表擅长“定位”
链表擅长“已定位后的连接修改”
```

真正选择时，再补上容量、空间、缓存和实现复杂度。
