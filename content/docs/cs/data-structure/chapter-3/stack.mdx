# 栈：只处理最近进入的元素

栈只允许在栈顶进行插入和删除：

```text
push：压入栈顶
pop：弹出栈顶
top/peek：读取栈顶但不删除
```

## 顺序栈：先明确 `top` 的含义

常见约定之一：`top` 表示当前栈顶元素下标，空栈时 `top=-1`。

```c
#define MAX_SIZE 100

typedef struct {
    int data[MAX_SIZE];
    int top;
} Stack;
```

### 入栈

```c
bool push(Stack *S, int x) {
    if (S->top == MAX_SIZE - 1) return false;
    S->top++;
    S->data[S->top] = x;
    return true;
}
```

### 出栈

```c
bool pop(Stack *S, int *x) {
    if (S->top == -1) return false;
    *x = S->data[S->top];
    S->top--;
    return true;
}
```

也有教材把 `top` 定义为“下一个可写位置”，此时空栈为 0。两种都正确，但判空、判满和操作顺序必须配套。

## 标例 1｜手动执行栈操作

初始为空，依次执行：

```text
push 1, push 2, pop, push 3, push 4, pop
```

过程：

```text
[]
[1]
[1,2]
pop 2 → [1]
[1,3]
[1,3,4]
pop 4 → [1,3]
```

最终栈顶为 3。

**复盘：**做操作序列题时直接画栈，不要只凭口头记忆。

## 链栈

把单链表头部作为栈顶，可在头部常数时间插入删除，通常不需要预设固定容量。

```c
bool push(Node **top, int x) {
    Node *s = malloc(sizeof(Node));
    if (s == NULL) return false;
    s->data = x;
    s->next = *top;
    *top = s;
    return true;
}
```

链栈仍可能因内存申请失败而无法入栈，只是没有顺序栈那种固定数组上限。

## 出栈序列如何判断

输入序列固定为 `1,2,3,...,n`，每个元素只能按顺序入栈，但可以在任意时刻出栈。

判断一个候选输出序列是否可能，最稳的方法是模拟：

1. 按输入顺序压栈，直到栈顶等于当前期望输出；
2. 相等就弹出并处理下一个输出；
3. 输入耗尽后仍无法匹配，则序列不可能。

### 标例 2

输入 `1,2,3,4`，输出 `2,1,4,3`：

- 压 1、2，弹 2；
- 弹 1；
- 压 3、4，弹 4；
- 弹 3。

因此可能。

输出 `3,1,2,4` 不可能：压入 1、2、3 后弹出 3，此时栈顶是 2，不可能先弹 1。

## 复杂度

在容量检查或内存申请视为常数时间时：

- `push`、`pop`、`peek` 均为 `Θ(1)`；
- 遍历整个栈为 `Θ(n)`。

## 高频易错点

- 没说明 `top` 是栈顶下标还是下一可写位置；
- 入栈前不判满，出栈前不判空；
- 弹出后错误访问已经无效的栈顶位置；
- 判断出栈序列时只看相邻元素，不做完整模拟；
- 认为链栈绝不会溢出。

## 30 秒速查

```text
LIFO：最近进入，最先离开
顺序栈常用约定：空 top=-1，满 top=MAX_SIZE-1
push：判满 → top++ → 写入
pop：判空 → 读取 → top--
出栈序列：按输入顺序模拟压栈和匹配
```
