# 整数表示：为什么补码最常用

给定 `n` 位，只能区分 `2^n` 种位模式。编码方案决定这些位模式分别对应哪些数。

## 无符号整数

所有位都表示数值，`n` 位范围为：

```text
0 到 2^n - 1
```

8 位无符号整数范围是 `0..255`。

## 原码、反码与补码

以 8 位为例，最高位作为符号信息：0 表示非负，1 表示负。

### 原码

正数：符号位 0，后面是绝对值。

```text
+5 → 00000101
-5 → 10000101
```

原码直观，但有 `+0` 和 `-0` 两个零，且加减电路不统一。

### 反码

正数与原码相同；负数在正数位模式基础上逐位取反：

```text
+5 → 00000101
-5 → 11111010
```

反码仍有两个零。

### 补码

正数与原码相同；负数常用“正数位模式逐位取反再加 1”得到：

```text
+5 → 00000101
取反 → 11111010
加 1 → 11111011  即 -5 的补码
```

补码只有一个 0，并能让加法器同时完成加法和减法，因此成为整数硬件的主流表示。

## `n` 位补码的范围

```text
-2^(n-1) 到 2^(n-1)-1
```

8 位补码范围：

```text
-128 到 127
```

负数比正数多一个，是因为 `10000000` 用来表示 `-128`，而零只有一种表示。

## 如何从补码读出负数

若最高位为 1，可以用两种方式：

### 方法 1：取反加 1 得绝对值

```text
11111101
取反 → 00000010
加 1 → 00000011
```

所以 8 位补码 `11111101` 表示 `-3`。

### 方法 2：最高位按负权处理

8 位补码的最高位权值是 `-2^7`，其余仍为正权：

```text
11111101
= -128 + 64 + 32 + 16 + 8 + 4 + 0 + 1
= -3
```

第二种方法对快速读值很方便。

## 同一位模式的两种解释

`11111101`：

```text
无符号：128+64+32+16+8+4+1 = 253
8 位补码：-3
```

位没有变化，变化的是解释指令和数据类型。

## 符号扩展：保持补码数值不变

把较短补码扩展到更长位宽时，复制符号位：

```text
8 位  10110110
16 位 11111111 10110110
```

因为原数为负，高位补 1 才能保持数值不变。正数则高位补 0。

无符号扩展通常高位补 0。

## 截断：直接丢高位可能改变数值

16 位数截成 8 位，只保留低 8 位。若被丢弃的高位不是原低位符号的正确扩展，数值会改变。

### 标例

```text
16 位：00000000 11110000 = 240
截成 8 位：11110000
```

若按无符号解释仍是 240；若按 8 位补码解释则是 -16。

因此截断不仅看保留了哪些位，还要看后续类型解释。

## `-128` 为什么不能在 8 位补码中取正

8 位正数最大是 127，没有位模式可表示 `+128`。对 `10000000` 取反加 1仍得到 `10000000`，这体现了固定宽度模运算，而不是它等于自己的数学相反数。

## 高频易错点

- 忘记先写位宽；
- 把无符号最高位也当符号位；
- 负数求补码时只取反不加 1；
- 认为补码范围正负对称；
- 符号扩展时负数高位补 0；
- 截断后仍按原位宽数值解释；
- 把“位模式相同”误认为“数值解释相同”。

## 30 秒速查

```text
n 位无符号：0 ... 2^n-1
n 位补码：-2^(n-1) ... 2^(n-1)-1
负数补码：正数位模式取反 + 1
补码读负数：取反 + 1，或最高位按负权
符号扩展：复制符号位
截断：保留低位，数值可能改变
```
